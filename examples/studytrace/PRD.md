# StudyTrace 学习证据助手——产品需求文档（PRD）

| 项目 | 内容 |
|---|---|
| PRD 版本 | 1.0 |
| 对应 BRD | `BRD.md` 1.0 |
| 文档状态 | 待需求确认 |
| MVP 平台 | 响应式 Web |
| 数据策略 | 浏览器本地优先，无账号 |

## 1. 产品概述

StudyTrace 帮助个人学习者建立“目标 → 今日任务 → 完成证据 → 周复盘”的闭环。第一版必须是可在手机和桌面浏览器中运行的完整产品，不依赖外部 AI、支付、邮件或文件存储服务。

### 产品原则

- 先帮助用户做出成果，再展示统计。
- 记录操作要短，证据有价值但不强迫。
- 明确数据保存在本地以及数据丢失风险。
- 不使用排行榜、羞辱性文案或连续打卡压力。
- 没有真实验证证据时，不把功能标记为通过。

## 2. 用户角色

MVP 只有一个本地用户角色，不含账号和管理员。

### 核心画像：小林

- 27 岁，工作日晚上学习前端开发。
- 已购买课程，但经常看完视频后没有完成练习。
- 希望 6 周后有一个可以放进作品集的应用。
- 主要用手机查看今天任务，用电脑完成练习并粘贴作品链接。

## 3. 核心用户旅程

### 首次使用

1. 用户看到一句价值说明和本地数据提示。
2. 用户创建学习目标，填写名称、截止日期和成功标准。
3. 用户创建第一个任务并安排到今天。
4. 用户完成任务，选择是否添加证据。
5. 首页展示下一步和本周进度。

### 日常学习

1. 用户打开“今天”。
2. 系统显示今天计划、已逾期未完成任务和预计总时长。
3. 用户完成任务并添加文字总结或 URL。
4. 系统即时保存并更新本周进度。

### 周复盘

1. 用户进入“复盘”。
2. 系统列出本周完成任务、证据数量和计划/实际情况。
3. 用户回答三个固定问题并保存。
4. 用户据此创建或调整下周任务。

## 4. 信息架构

- `/today`：今天、逾期任务、快速完成。
- `/goals`：目标列表、创建目标、归档目标。
- `/goals/:id`：目标详情、任务和证据时间线。
- `/review`：本周数据和周复盘。
- `/settings`：数据导入、导出、清空和隐私说明。

首次打开且没有目标时显示引导页；创建首个目标后默认进入 `/today`。

## 5. 功能需求

### FR-01 创建和管理学习目标

字段：

| 字段 | 规则 |
|---|---|
| 目标名称 | 必填，1–60 字符 |
| 成功标准 | 必填，1–300 字符，应描述可观察结果 |
| 截止日期 | 必填，不早于今天，默认 6 周后 |
| 状态 | `active`、`completed`、`archived` |

规则：最多同时存在 3 个 `active` 目标。用户可以编辑、完成或归档目标；删除目标前必须明确说明其任务和证据将一起删除，并要求二次确认。

### FR-02 创建和安排学习任务

任务字段：标题、所属目标、计划日期、预计分钟数、备注、状态、创建时间、完成时间。

- 标题必填，1–100 字符。
- 预计时长为 5–240 分钟，步长 5 分钟。
- 计划日期可以为空；为空时进入目标的“待安排”区域。
- 状态为 `todo` 或 `done`。
- 用户可以编辑、删除、改期和恢复已完成任务。

### FR-03 今天视图

今天视图按照以下顺序显示：

1. 逾期且未完成的任务。
2. 计划日期为今天且未完成的任务。
3. 今天已经完成的任务。

页面显示未完成任务预计时长合计。没有任务时提供创建任务入口，不显示空白页面。

### FR-04 完成任务与学习证据

点击完成后打开轻量完成面板：

- 文字证据：0–500 字符。
- 链接证据：可选，只接受 `http://` 或 `https://` URL。
- 用户可以不填证据直接完成，但界面提示“写下一句话或粘贴作品链接，方便以后复盘”。
- 保存后任务立即显示为完成；证据可再次编辑。
- 每个任务 MVP 只保存一条证据记录，其中可同时包含文字和 URL。

### FR-05 目标详情与进度

目标详情显示：

- 成功标准和截止日期。
- 已完成任务数 / 总任务数。
- 有证据的完成任务数。
- 按日期倒序的任务及证据时间线。
- 新建任务、编辑目标、完成目标和归档入口。

若目标没有任务，显示如何创建第一个可在 15–60 分钟内完成的小任务。

### FR-06 周复盘

周范围固定为用户本地时间周一 00:00 至周日 23:59。页面展示当周：

- 计划任务数、完成任务数、完成率。
- 完成任务预计分钟数总和。
- 证据记录数。
- 按目标分组的完成任务。

固定复盘问题：

1. 本周最重要的学习成果是什么？
2. 什么阻碍了你？
3. 下周最重要的一步是什么？

每题最多 500 字符；同一周只有一份复盘，可持续编辑。

### FR-07 本地保存与恢复

- 每次创建、编辑、完成或删除后立即保存到浏览器持久化存储。
- 刷新、关闭页面再打开时数据仍存在。
- 存储失败时显示明确错误，不得假装已保存。
- 首次使用时说明“数据仅保存在当前浏览器，清理浏览器数据可能导致丢失”。

### FR-08 数据导出、导入和清空

- 导出为带 schema 版本和导出时间的 UTF-8 JSON 文件。
- 导入前验证 JSON 结构；显示将新增/覆盖的数据摘要，再要求确认。
- MVP 的导入策略为完整覆盖，不做合并。
- 导入失败不得改变现有数据。
- 清空全部数据需要输入产品名 `StudyTrace` 二次确认。

## 6. 数据模型

### LearningGoal

`id`, `name`, `successCriteria`, `deadline`, `status`, `createdAt`, `updatedAt`

### LearningTask

`id`, `goalId`, `title`, `scheduledDate`, `estimatedMinutes`, `note`, `status`, `createdAt`, `updatedAt`, `completedAt`

### Evidence

`id`, `taskId`, `text`, `url`, `createdAt`, `updatedAt`

### WeeklyReview

`id`, `weekStart`, `achievement`, `blocker`, `nextStep`, `createdAt`, `updatedAt`

### ExportEnvelope

`schemaVersion`, `exportedAt`, `goals`, `tasks`, `evidence`, `weeklyReviews`

所有 ID 使用应用生成的唯一字符串。日期时间保存为 ISO 8601；计划日期和 `weekStart` 保存为本地日历日期 `YYYY-MM-DD`。

## 7. 状态与异常要求

每个页面必须定义并实现：

- loading：从本地存储恢复数据时。
- empty：没有目标、没有今天任务、没有周记录时。
- error：读取、保存或导入失败时。
- disabled：提交中、字段无效或达到 3 个活动目标上限时。
- success：保存成功应通过界面状态变化体现，避免频繁弹窗。

网络离线不影响核心功能。外部证据链接只作为链接保存，不自动抓取页面标题或内容。

## 8. 交互与视觉要求

- 移动端 320px 起可用，主要操作可单手完成。
- “完成任务”是今天页面的主要操作，但不能因颜色成为唯一识别方式。
- 逾期表示使用中性提醒，不使用羞辱或威胁文案。
- 删除、覆盖导入、清空数据属于高风险操作，必须二次确认。
- 所有表单字段有可见标签、错误提示和键盘焦点状态。
- 支持系统浅色/深色偏好；首版不要求用户手动切换主题。
- 使用简体中文；日期显示符合中文阅读习惯。

## 9. 非功能需求

### 性能

- 在中等性能手机、1000 条任务以内，首屏本地数据恢复目标 ≤ 1 秒。
- 常用创建、完成和筛选操作的界面反馈目标 ≤ 100 毫秒。
- 生产构建不得包含阻塞核心功能的第三方运行时请求。

### 可用性与兼容性

- 支持最近两个主要版本的 Chrome、Edge、Safari 和 Firefox。
- 关键流程可仅用键盘完成。
- 文本与背景颜色对比达到 WCAG 2.2 AA 的相关要求。
- 用户输入在显示时必须转义，URL 必须验证协议。

### 隐私与安全

- 不需要注册，不收集姓名、邮箱、位置和设备联系人。
- 不把本地数据发送给服务器、分析平台或错误追踪服务。
- 不在日志中输出证据正文或复盘正文。
- 应用内清楚说明本地保存、导出和删除方式。

## 10. 产品事件定义

MVP 不向外部分析服务发送数据，但代码应以不含正文的本地事件接口记录以下事件，方便可用性测试时由用户主动导出：

- `goal_created`
- `task_created`
- `task_completed`
- `evidence_added`
- `weekly_review_saved`
- `data_exported`

事件属性只允许时间、目标/任务匿名 ID、预计分钟数和是否包含证据；不得包含标题、URL 或正文。

## 11. 验收标准

### AC-01 首次闭环

给定全新浏览器数据，用户可以创建目标、创建今天任务、完成任务并添加文字证据；刷新页面后四类数据仍然存在。

### AC-02 活动目标上限

给定已有 3 个活动目标，创建按钮进入禁用状态并解释上限；归档其中一个目标后可以再次创建。

### AC-03 今天排序

给定逾期、今天和已完成任务，页面始终按“逾期未完成 → 今天未完成 → 今天已完成”分组显示。

### AC-04 证据校验

输入非 `http/https` 链接时不能保存并显示字段错误；只填写文字、只填写合法链接、两者都填或两者都不填均能按规则完成任务。

### AC-05 周边界

给定跨周任务，周复盘只统计本地时间当周完成的任务；周一和周日边界测试通过。

### AC-06 导入原子性

导入结构无效的 JSON 时显示错误且原数据不变；导入有效备份并确认后数据完整恢复。

### AC-07 高风险操作

删除目标、覆盖导入和清空全部数据都不能通过一次误触完成。

### AC-08 响应式和键盘操作

在 320px、768px、1280px 宽度下核心内容无水平溢出；仅用键盘可以完成创建目标、创建任务、完成任务和保存复盘。

### AC-09 生产构建

安装、静态检查、单元测试和生产构建命令退出码均为 0；构建产物可在本地预览并完成 AC-01。

## 12. 测试数据

演示目标：“6 周完成一个响应式作品集网站”。

示例任务：

- 今天：完成首页线框图，预计 45 分钟。
- 今天：实现项目卡片组件，预计 60 分钟。
- 逾期：整理 3 个项目介绍，预计 30 分钟。
- 待安排：请朋友检查移动端体验，预计 20 分钟。

示例证据只使用公开占位 URL，不放真实私人文档。

## 13. 发布范围和完成定义

MVP 完成必须同时满足：

1. FR-01 至 FR-08 全部实现。
2. AC-01 至 AC-09 有可复现证据。
3. 无高优先级已知数据丢失问题。
4. 固定手册要求的 loading、empty、error、disabled、success 状态已覆盖。
5. 上线手册、隐私说明、数据备份与回滚路径完成。
6. 需求、功能、视觉和上线四个人工关口均由对应负责人明确批准。

## 14. 已冻结决策

- MVP 无账号、无云同步、无 AI、无支付。
- 周一为一周开始，使用浏览器本地时区。
- 证据仅为文字和 URL，不上传文件。
- 最多 3 个活动目标。
- 不提供连续打卡天数和排行榜。
- 导入使用完整覆盖，导入前必须确认，失败保持原数据。

这些决策如有变化，需要更新 PRD 版本，并重新评估受影响的技术、测试、视觉和上线产物。
