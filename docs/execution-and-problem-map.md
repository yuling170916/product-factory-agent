# 产品工厂执行流程与问题地图

## 执行流程

```mermaid
flowchart TD
    A["输入：已确定 PRD"] --> B["1. PRD 归档"]
    B --> G1{"人工：需求确认"}
    G1 -->|拒绝| R1["补充/修改 PRD"] --> B
    G1 -->|批准| C["2. 技术选型"]
    C --> D["3. 开发技术文档"]
    D --> E["4. 首轮开发验证"]
    E --> G2{"人工：功能验收"}
    G2 -->|拒绝| R2["修改技术方案或原型"] --> D
    G2 -->|批准| F["5. 项目级前端手册"]
    F --> H["6. 视觉风格方案"]
    H --> G3{"人工：交互/视觉验收"}
    G3 -->|拒绝| R3["调整交互与视觉方案"] --> H
    G3 -->|批准| I["7. 前后端开发与联调"]
    I --> J["8. 集成版本开发验证"]
    J --> K["9. 上线手册"]
    K --> G4{"人工：权限与上线决策"}
    G4 -->|拒绝| R4["补权限、监控或回滚方案"] --> K
    G4 -->|批准| L["显式执行部署命令"]
    L --> M["10. 线上版本验证"]
    M --> N["输出：本地与线上可验证版本"]
```

自动阶段可以连续推进；菱形节点必须由人给出可审计的批准或拒绝。拒绝会留在当前关口，不能跳到后续阶段。

## 不能替代的事情

- 不能证明一个未经访谈的商业假设一定成立。
- 不能替业务负责人接受需求和经营风险。
- 不能替设计负责人完成主观视觉判断。
- 不能在没有账号、权限和目标环境时证明线上通过。
- 不能保证自动生成代码天然安全、合规或没有缺陷。

它真正减少的是流程遗漏、重复文档劳动和无证据的“口头完成”；它保留的是必须由人承担的判断与责任。
