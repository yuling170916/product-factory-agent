# 技术栈手册（固定资产）

选择技术栈时按以下优先级决策，并在项目级技术选型中记录理由和被否决方案。

1. 先满足 PRD 的约束、团队能力、交付期限、合规和运行环境。
2. 优先成熟、维护活跃、文档充分、可测试、可观测的技术。
3. MVP 默认单体优先；没有明确的容量或隔离证据，不引入微服务。
4. 数据模型、认证授权、密钥管理、备份恢复必须显式设计。
5. 所有版本使用 lockfile 或等价机制固定；不得只写“使用最新版”。
6. 技术选型必须给出本地开发、测试、构建、部署和回滚路径。

技术选型文档至少包含：需求驱动因素、架构图（文本或 Mermaid）、前端、后端、数据层、部署平台、测试策略、风险、替代方案和 ADR。
